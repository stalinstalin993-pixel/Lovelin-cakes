# Pistachio & Petal

A complete, static, mobile-first website for a home cake bakery. It ships with 88 sample cakes, a live customizer, a local cart, and WhatsApp checkout — no backend required.

> **This is still a demo.** The bakery name, owner, address, phone number, social links, reviews, maps links, domain, and all photography are placeholders. See [Before launch](#before-launch) for the exact checklist.

## Quick start

Requirements: **Node.js 20+** and npm.

```bash
npm install
npm run dev
```

`npm run dev` builds the CSS and JavaScript, then serves the site at **http://localhost:3000**.

Useful commands:

| Command | What it does |
| --- | --- |
| `npm run dev` | Build everything and start the local server |
| `npm run build` | Production build: CSS, JS minification, offline catalog sync |
| `npm run build:netlify` | Build, then assemble the deploy-only `dist/` folder |
| `npm run assets` | Regenerate placeholder cake/gallery images, icons, QR, OG cover |
| `npm run catalog` | Build `catalog.pdf` (9 cakes per A4 page) |
| `npm run sync-fallback` | Copy `cakes.json` into the offline fallback in `app.js` |
| `npx serve .` | Alternative static preview after `npm run build` |

Do not open `index.html` directly from the file system. The catalog and fonts are fetched over HTTP, so use a local server. If fetching fails, the site falls back to the embedded catalog, but a server is still the correct way to test.

Source versus generated files:

- Edit `src/input.css`, `app.js`, `admin.js`, `festive.js`, `404.js`.
- Do **not** edit `styles.css`, `app.min.js`, `admin.min.js`, `festive.min.js`, or `404.min.js` — they are generated by `npm run build`.

## What is included

- **Storefront:** editorial hero, category chips with counts, name/code search, price sorting, 24-at-a-time catalog, lazy images, image lightbox.
- **Cake customizer:** weight (minimum to 8 kg in 0.5 kg steps), free/premium flavours, eggless surcharge, message on cake, special instructions, live price.
- **Cart:** slide-over on desktop, bottom sheet on mobile, quantity controls, localStorage persistence with safe fallbacks.
- **WhatsApp checkout:** name, pickup/delivery, address, date, hourly time slot, validation, emoji-formatted order message with each cake’s photo URL.
- **Content sections:** custom-order steps, masonry gallery, why-us, reviews, baker story, FAQ accordion, contact, map, QR code.
- **Optional admin:** Supabase authentication, cake CRUD, photo upload, tags, reordering, starter-catalog import.
- **Festive skins:** Christmas, Deepavali, New Year, Valentine’s, Pongal — date-driven or forced by URL, loaded on demand.
- **Deploy assets:** SEO metadata, Bakery/LocalBusiness JSON-LD, FAQ JSON-LD, Open Graph/Twitter cards, sitemap, robots, manifest, favicons, Netlify headers/redirects.
- **Extras:** `404.html`, printable catalog generator, README, design tokens.

## Design system

**Direction:** Pistachio Patisserie — a modern French café feel. Editorial whitespace, arch-shaped imagery, thin ink outlines, butter-highlight cards, and berry CTAs.

### Colour

| Token | Hex | Use |
| --- | --- | --- |
| Ink | `#1F2A24` | Body text, footer, dark sections |
| Pistachio | `#A8C69F` | Brand washes, icons, decorative accents |
| Sage 50 | `#F3F7F1` | Page background |
| Sage deep | `#E3EDDC` | Section tints, image backgrounds |
| Butter | `#F6E7B4` | Highlights, badges, dark-section CTA |
| Berry | `#8E3B5A` | Prices, primary buttons, accent words |
| White | `#FFFFFF` | Cards, fields |

Tokens live in `src/input.css` under `@theme`. Change them there and rebuild.

### Type

- **Fraunces** 300–700 — display headings; italic for accent words. Self-hosted.
- **DM Sans** 300–700 — body and UI. Self-hosted.
- **Space Grotesk** 300–700 — uppercase labels, codes, prices, FAQ eyebrows. Self-hosted.
- Latin WOFF2 files are in `fonts/`. The Tamil accent line falls back to the device’s Tamil font; no extra download. All three families are SIL Open Font License 1.1; see `fonts/README.md`.

### Layout and shape

- Content width: `78rem` maximum, `1.25rem` gutters on mobile, `2rem` from 640px.
- Section rhythm: `clamp(3.5rem, 8vw, 6.5rem)` vertical padding.
- Radii: 24px cards, pill buttons/chips, arch frames (`999px 999px 24px 24px`).
- Borders: 1px ink at low opacity; shadows only on hover and overlays.
- Breakpoints: 640px, 768px, 900px, 1100px, 1200px.

### Components

Pill buttons (berry / ink / outline / butter), category chips, cake cards, code and tag badges, option buttons, switch, fields, cart lines, quantity steppers, drawer, modal, lightbox, FAQ accordion, review cards, trust chips, toast, floating WhatsApp button.

Decorative details: subtle SVG grain over the hero, hand-drawn squiggle underlines, whisk/cherry doodles, and a slowly spinning “freshly baked” stamp.

### Motion

- Fade-up scroll reveals via IntersectionObserver (below-the-fold only; the hero renders immediately for LCP).
- Cards lift 4px on hover; photos scale 1.035.
- Cart badge bounces when an item is added.
- Modals trap focus, close on Esc, return focus to the trigger.
- `prefers-reduced-motion` removes animation and smooth scrolling.

### 1. Business details

Edit `site.config.js`. The file is the runtime source of truth for:

- Bakery name, owner, tagline, town, address, pin, state
- Phone, WhatsApp number, email, Instagram, Facebook
- Google Maps link, map embed URL, Google review link
- Working hours, delivery hours, delivery note/fee
- Advance notice, payment and cancellation copy
- Weight limits, excluded weights, surcharges
- Free and premium flavours
- Reviews shown on the page
- Announcement text
- Supabase credentials (optional)
- Festive behaviour and offer copy

The WhatsApp number must be digits only with country code, e.g. `919876543210`.

Some copy is duplicated in `index.html` on purpose so search engines and social previews get real HTML without JavaScript. Update both places:

- `<title>`, meta description, canonical, Open Graph/Twitter tags
- Bakery + FAQ JSON-LD
- Contact address, hours, phone, email in the contact section and footer
- Map embed URL and “Get directions” links
- Review links (marked `data-review-link`)
- 404 page phone/WhatsApp fallback
- `sitemap.xml` and `robots.txt` domain
- `site.webmanifest` name/description

Replace the domain `https://pistachioandpetal.netlify.app` with the live domain everywhere, including `site.config.js → siteUrl`.

### 2. Reviews

The five reviews in `site.config.js` are sample copy. Replace them with real Google reviews (with permission). Update `reviewRating`, `reviewCount`, and `reviewUrl`.

### 3. Photography

The repository contains generated illustration placeholders, not photographs. Replace them before launch. See [Images the owner needs](#images-the-owner-needs).

`npm run assets` regenerates placeholders and **overwrites the image files**. Do not run it after adding real photos unless you have backed them up.

### 4. Test a real order

Use your own phone. Add a cake, open the cart, choose a date/time, place the order, check the WhatsApp message, and confirm the photo URL opens publicly.

## Catalog & pricing

### Source of truth

`cakes.json` contains the catalog used by the storefront. `app.js` also embeds a compact fallback generated from it, so the menu still works if the JSON fetch fails.

When Supabase is configured in `site.config.js`, the storefront reads Supabase first. If Supabase returns no rows or errors, it falls back to `cakes.json`, then to the embedded copy. The admin page is the easiest way to edit after Supabase is connected; otherwise edit `cakes.json`.

### Cake fields

```json
{
  "code": "BD09",
  "name": "Garden Party Cake",
  "category": "birthday-girl",
  "price": 1550,
  "minWeight": 1,
  "image": "images/cakes/BD09.webp",
  "flavourChoice": true,
  "noEggless": false,
  "tags": ["new", "kids"],
  "order": 89
}
```

| Field | Notes |
| --- | --- |
| `code` | 2–12 characters, uppercase, unique. Shown on cards and in the WhatsApp message. |
| `category` | One of the IDs below. |
| `price` | Price in INR at `minWeight`. |
| `minWeight` | Minimum order weight in kg. Use `0.5` for bento boxes and most boxes. |
| `image` | Path or absolute URL. Recommended 800 × 1000 WebP. |
| `flavourChoice` | `false` hides the flavour picker (used for cheesecakes and boxes). |
| `noEggless` | `true` disables the eggless toggle and shows “Contains egg”. |
| `tags` | `new`, `bestseller`, `trending`, `kids`, `premium`, `seasonal`. `new`/`bestseller`/`trending` become badges. |
| `order` | Catalog order and “popular” sort. |

Category IDs: `signature`, `trending`, `chocolate`, `fruit`, `premium`, `cheesecakes`, `special-occasion`, `birthday-boy`, `birthday-girl`, `wedding-anniversary`, `brownies-cupcakes`.

### Add a cake with JSON

1. Add the photo at `images/cakes/<CODE>.webp` (800 × 1000 recommended).
2. Add a thumbnail at `images/cakes/thumbs/<CODE>.webp` (400 × 500). This is optional: if it is missing, the card retries the full image automatically.
3. Append the object to `cakes.json`.
4. Run `npm run build`. This syncs the fallback and recompiles CSS/JS.
5. Hard-refresh and check the card, lightbox, customizer, and WhatsApp message.

To remove a cake, delete its object (and optionally the images). To reorder, change `order`; lower numbers appear first.

### Price formula

```text
unit price =
  (cake.price ÷ cake.minWeight
   + premium flavour surcharge per kg
   + eggless surcharge per kg)
  × chosen weight
```

The final amount is rounded to the nearest rupee. Defaults: premium flavours `+₹150/kg`, eggless `+₹100/kg`.

Example: a 1.5 kg cake priced at ₹1,450 per 1 kg, with Blueberry and eggless:
`(1450 + 150 + 100) × 1.5 = ₹2,550`.

### Change prices, weights, and flavours

Edit `site.config.js`:

| Setting | Default |
| --- | --- |
| `maxWeight` | `8` kg |
| `weightStep` | `0.5` kg |
| `excludedWeights` | `[]` — e.g. `[0.5, 5.5]` |
| `egglessSurcharge` | `100` per kg |
| `premiumSurcharge` | `150` per kg |
| `freeFlavours` | White Forest, Black Forest, Mango, Pineapple, Strawberry, Black Currant, Vanilla |
| `premiumFlavours` | Rasamalai, Blueberry, Butterscotch, Choco Truffle, Honey Almond |
| `deliveryHours` | 10:00–21:00; time slots are generated hourly |

Per-cake prices and minimum weights belong in `cakes.json` (or Supabase).

## Cart and WhatsApp checkout

- The cart is stored in `localStorage` under `pp_cart_v1`, wrapped in `try/catch` so private mode never breaks the page.
- Each line item keeps code, name, weight, flavour, eggless, message, instructions, unit price, and quantity.
- Required checkout fields: name, pickup/delivery, delivery address (delivery only), date (today or later), time slot.
- The date input defaults to tomorrow and cannot select past dates.
- “Place order on WhatsApp” builds a message and opens `https://wa.me/<number>?text=...`.

Example message:

```text
🎂 New Order – Pistachio & Petal
Name: Anu
Date: 4 Nov 2026 | Time: 10:00 AM
Mode: Pickup

1) SG01 – Pistachio Rose Cloud
   1.5 kg · Blueberry · Eggless · Qty 1
   Message: "For Amma"
   Notes: Less sweet, please
   Photo: https://your-domain.com/images/cakes/SG01.webp
   ₹2,550

Subtotal: ₹2,550
(Final price confirmed by the bakery)
```

No payment is taken on the site. Delivery charges and availability are confirmed by the bakery on WhatsApp.

## Admin setup (Supabase)

The admin is optional. The storefront works entirely without it.

### 1. Create a project

1. Sign in at [supabase.com](https://supabase.com) and create a free project.
2. Open **SQL Editor**.
3. Paste and run `supabase/setup.sql`.

This creates:

- `public.cakes` with indexes and an `updated_at` trigger.
- Row-level security: public `SELECT`; insert/update/delete only for `authenticated`.
- A public `cake-photos` storage bucket (5 MB limit, WebP/JPEG/PNG only), with public read and authenticated write policies.

### 2. Create the bakery user

1. Go to **Authentication → Users → Add user**.
2. Create an email/password user and confirm the email (or disable email confirmation for this user).
3. There is intentionally no public sign-up form.

### 3. Connect the site

In `site.config.js`:

```js
supabase: {
  url: "https://YOUR-PROJECT.supabase.co",
  anonKey: "YOUR-ANON-KEY",
  table: "cakes",
  bucket: "cake-photos",
}
```

Find both values under **Project Settings → API**. The anon key is safe to expose in a browser; row-level security is what protects writes. Never put the `service_role` key in this repository.

Rebuild/deploy. Open `/admin.html`, sign in, and click **Import starter menu** to copy `cakes.json` into Supabase.

### 4. Admin features

- Add, edit, delete cakes
- Upload photos directly to Supabase Storage
- Reorder with the up/down controls (updates `sort_order`)
- Toggle Trending and New arrival tags
- Search by name or code
- Import/update the starter catalog without creating duplicates

`admin.html` is `noindex`, and `_headers` adds `X-Robots-Tag: noindex` as a second guard.

### 5. Notes

- The storefront reads Supabase when configured; `cakes.json` remains the fallback.
- If a Supabase image is a full URL, the card uses it directly (no thumbnail srcset).
- The admin stores its session in `sessionStorage` and refreshes the access token when needed.
- To go back to JSON-only mode, blank out `supabase.url` and `supabase.anonKey`.

## Festive themes

Configure in `site.config.js`:

```js
festive: {
  enabled: true,
  mode: "auto",        // "auto" | "fixed" | "off"
  theme: null,         // used when mode is "fixed"
  offers: { ... },
  announcementByTheme: { ... },
}
```

- `auto` follows approximate date windows in `festive.js`: New Year (28 Dec–2 Jan), Pongal (13–18 Jan), Valentine’s (7–15 Feb), Deepavali (25 Oct–12 Nov), Christmas (1–27 Dec).
- `fixed` locks one theme. Valid values: `christmas`, `deepavali`, `new-year`, `valentines`, `pongal`.
- `off` disables themes.

Force a theme for testing without changing config:

```text
/?festive=christmas
/?festive=off
```

Theme CSS is loaded only when a theme is active, so the base site has no festive render-blocking request. Deepavali moves each year; adjust the range in `festive.js`.

Each theme adds a decorative fixed layer (CSS gradients only), updates the announcement text, and re-colours the announcement bar. The close button remains respected. All motion is disabled under `prefers-reduced-motion`.

## Deploy to Netlify

### Option A — Git (recommended)

1. Push the project to GitHub/GitLab/Bitbucket.
2. In Netlify: **Add new site → Import an existing project**.
3. Choose the repository.
4. Netlify reads `netlify.toml` automatically:
   - Build command: `npm run build:netlify`
   - Publish directory: `dist`
5. Node version is pinned in `netlify.toml` (`NODE_VERSION = "20"`).
6. Deploy.

The build creates a clean `dist/` folder containing only the site (no `node_modules`, source files, scripts, or printable catalog). `dist/` is gitignored.

`netlify.toml`, `_headers`, and `_redirects` are included. Netlify will:

- Compile Tailwind into `styles.css`
- Minify the storefront/admin scripts
- Sync the offline catalog from `cakes.json`
- Apply cache and security headers
- Serve `404.html` for missing paths

### Option B — Netlify CLI

```bash
npm install
npm run build:netlify
npx netlify-cli deploy --dir dist --prod
```

### After the first deploy

1. Add a custom domain in Netlify and enable HTTPS.
2. Replace `https://pistachioandpetal.netlify.app` with the real domain in:
   - `site.config.js` (`siteUrl`)
   - `index.html` (canonical, Open Graph, Twitter, JSON-LD)
   - `sitemap.xml`
   - `robots.txt`
3. Redeploy.
4. Test:
   - WhatsApp link opens the correct number and message
   - Order message photo URLs use the live domain
   - Google Map and directions link point to the real shop
   - `/admin.html` loads and Supabase sign-in works (if configured)
   - `/does-not-exist` shows the 404 design
   - Mobile menu, cart, customizer, lightbox, FAQ
5. Submit `sitemap.xml` in Google Search Console.

### Caching

`_headers` sets:

- Images and fonts: one year, immutable
- CSS/JS: one hour with stale-while-revalidate
- HTML: revalidate
- Security headers: CSP, nosniff, frame options, referrer policy, permissions policy

If you change an image but keep the same filename, browsers may keep the old cached copy for up to a year. Rename the file or add a query-string version.

## Quality checks

Tested at 360px, 390px, 768px, and 1280px with no horizontal page overflow. The checkout message, admin CRUD (against mocked Supabase), focus handling, Esc closing, localStorage cart, and image fallbacks were exercised in a real browser.

Local Lighthouse (mobile, Chrome headless, festive off):

| Category | Score |
| --- | --- |
| Performance | 92 |
| Accessibility | 100 |
| Best Practices | 100 |
| SEO | 100 |

Scores vary with network conditions, third-party map availability, and how many images are cached; repeated local runs ranged from 92 to 95 for performance. The map iframe is lazy-loaded and does not block the initial render.

### Accessibility notes

- Semantic landmarks, skip link, visible focus rings.
- Modals/drawer trap focus, close on Esc, return focus.
- Tap targets are at least 44px for interactive controls.
- Images have descriptive alt text; decorative images are empty-alt.
- `prefers-reduced-motion` disables reveals and festive animation.
- Form fields have labels; errors use `role="alert"`.
- Colour pairings were checked for AA contrast.

### Security notes

- No backend, no payment handling, no API secrets in the repo.
- Supabase anon key is public by design; RLS limits writes to authenticated users.
- CSP, `X-Content-Type-Options`, frame options, referrer policy, and permissions policy are set in `_headers`.
- The CSP allows `'unsafe-inline'` for JSON-LD data blocks and the style attributes used by the design system. If you remove inline styles/JSON-LD, tighten it further.

## A few practical notes

- Prices shown are the price at the minimum weight. The customizer recalculates per kg.
- Cheesecakes and boxed bakes have no flavour picker (`flavourChoice: false`).
- Cakes marked `noEggless: true` still show a clear “Contains egg” note.
- Order dates are local to the customer’s browser; confirm the date on WhatsApp.
- The QR code points at `https://wa.me/<number>?text=...` and is regenerated by `npm run assets`.
- Festive dates are approximate because Deepavali moves each year. Adjust `festive.js` if needed.
- If you add a new category, add it to `CATEGORIES` in `app.js` and to the admin `<select>` in `admin.html`.
